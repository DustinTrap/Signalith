          Findings

          Risk

          Detections add risk to the users and systems in their results. Scores are multiplied by asset and identity priority (critical ×2, high or watchlisted ×1.5, low ×0.5). The risk incident detections raise a finding when an object passes 100 in a day or spans three ATT&CK tactics in a week.

          Assets & identities

          Tell Signalith which hosts and accounts matter. Priority raises the urgency of findings and multiplies risk; owner and category show next to findings and in search with | enrich. Export these from your CMDB or directory as CSV. Separate multiple values in one cell with |.

          Assets

          Download CSV

          Columns: host, ip, cidr, owner, priority, category, bunit, location. Each row needs a host, ip or cidr. Priority is low, medium, high or critical.

          Threat intel

          Indicators are known-bad IP addresses and networks, domains, URLs, file hashes and email addresses. Signalith downloads them from the feeds in signalith.yaml and you can add your own. The Threat intel match detection checks new events every 5 minutes and adds risk scaled by each indicator's weight. In Search, | threatmatch keeps only matching events and | intel adds intel columns to any result.

          Feeds

          Example feed settings

          Paste into signalith.yaml, run signalith validate, and restart. Feeds download right away, then on their interval. Check each provider's terms of use.

          intel:
  feeds:
    # Botnet command-and-control servers (abuse.ch Feodo Tracker)
    - name: feodo-tracker
      url: https://feodotracker.abuse.ch/downloads/ipblocklist.txt
      tags: [botnet, c2]
      weight: 1.5
    # Malware download URLs from the last 30 days (abuse.ch URLhaus)
    - name: urlhaus
      url: https://urlhaus.abuse.ch/downloads/csv_recent/
      format: csv
      column: url
      type: url
    # Malware file hashes (abuse.ch MalwareBazaar, last 48 hours)
    - name: malwarebazaar
      url: https://bazaar.abuse.ch/export/txt/sha256/recent/
      type: sha256
    # Compromised hosts (Proofpoint Emerging Threats)
    - name: et-compromised
      url: https://rules.emergingthreats.net/blockrules/compromised-ips.txt
      type: ip
      interval: 12h
    # A STIX 2.1 bundle from your own platform, with an API key
    - name: our-misp
      url: https://misp.example.com/feeds/signalith.json
      format: stix
      headers: {Authorization: "${MISP_API_KEY}"}

            Query guide
            
    
            A query is a search followed by commands joined with |. The search picks events; each command reshapes the results.
            
    
            Search
            
    
            
      
            datamodel=AuthenticationOnly events of one data model (Authentication, Endpoint, Network_Traffic, Change, Other, Risk)
            
      
            user=adminField equals a value (case-insensitive)
            
      
            user=adm*Wildcards with *
            
      
            dest_port>=1024Comparisons: = != < <= > >=
            
      
            src IN (10.0.0.1, 10.0.0.2)Any of several values
            
      
            "failed password"Text anywhere in the raw event
            
      
            a=1 b=2 OR c=3Terms are ANDed; OR binds tighter, as in SPL; use NOT and parentheses as needed
            
      
            earliest=-7d@d latest=nowTime range; overrides the time picker
            
    
            
    
            Commands
            
    
            
      
            | stats count, dc(user) as users by srcAggregate: count, dc, sum, avg, min, max
            
      
            | timechart span=1h count by actionSeries over time
            
      
            | top limit=10 process_nameMost common values with percentages
            
      
            | where count > 20Filter rows; uses AND/OR like most languages
            
      
            | sort -count, srcSort; - for descending
            
      
            | head 10Keep the first N rows
            
      
            | table _time, user, srcChoose columns
            
      
            | rename src as source_ipRename columns
            
      
            | enrichAdd owner, priority and category from the asset and identity lists, as dest_owner, user_priority and so on
            
      
            | threatmatchKeep only events whose IP, domain, URL, hash or email fields match threat intel, with threat_match_value, threat_source and threat_weight columns. Name fields to check only those: | threatmatch src, dest. Put it right after the search
            
      
            | intel src, destCheck any result against threat intel: adds src_intel_source, src_intel_type, src_intel_weight and src_intel_description where a value is a known indicator
